# موسوعة لينكس العربية — حزمة الإصدار المتصل

هذه الحزمة تطوّر نسخة الموقع الحالية وتحافظ على تصميمها وملف الأوامر الأصلي مع إصلاح تنسيق `commands.json` حتى يصبح JSON صالحاً للتحميل.

## ما الذي تحتويه الحزمة؟

- تسجيل حساب وتسجيل دخول بالبريد الإلكتروني وكلمة المرور عبر Supabase Auth، مع اسم عرض مستقل.
- ربط قراءة تقدم الأوامر والإنجازات بجدول `lesson_progress` في مشروع Supabase الحالي.
- حفظ نتائج الاختبارات بعد تصحيح الإجابات داخل Edge Function، وليس بمجرد نتيجة يرسلها المتصفح.
- بوابة Telegram: رابط ربط مؤقت لمرة واحدة، وربط هوية Telegram بحساب Supabase، ثم التحقق من عضوية قناة `@something_37` بواسطة البوت.
- طرفية تعليمية بمحاكاة نظام ملفات افتراضي داخل المتصفح، ومحرر Python/Bash بتشغيل تدريبي محدود.
- شرح متعمّق لكل أمر في الموسوعة. الأوامر الشائعة لها شروحات خاصة، وبقية الأوامر تحصل على شرح منظّم مبني على وصف الأمر مع إرشادات الرجوع إلى `man`.
- حجب عناصر المستويين المتوسط والمتقدم من واجهة الموسوعة والاختبارات حتى استيفاء الشروط.

## الملفات المهمة

- `index.html`, `styles.css`, `app.js`, `config.js`: ملفات واجهة الموقع.
- `commands.json`: قاعدة بيانات الأوامر وعددها 1500.
- `assets/JINX.png`: صورة الواجهة المستخدمة في التصميم.
- `supabase/migrations/202610300001_linux_ar_auth_rls.sql`: ربط ملف المستخدم وإعداد سياسات RLS.
- `supabase/functions/telegram-gateway/index.ts`: ربط Telegram والتحقق من العضوية وتصحيح الاختبارات على الخادم.
- `supabase/config.toml`: إعداد نشر الوظيفة.

## 1) استبدال ملفات الموقع محلياً

1. احتفظ بنسخة احتياطية من مجلد الموقع القديم.
2. استخرج محتويات هذه الحزمة داخل مجلد الموقع الذي يخدم العنوان المحلي:
   `http://127.0.0.1:8000/linux-arabic-academy/`
3. وافق على استبدال الملفات المتطابقة، وتأكد أن `index.html` و`app.js` و`styles.css` و`config.js` و`commands.json` موجودة في المجلد نفسه، وأن مجلد `assets` موجود بجانبها.
4. لا تحتاج إلى إنشاء خادم محلي جديد إذا كان الخادم الحالي يعمل على المنفذ 8000.

ملف `config.js` يحتوي عنوان مشروع Supabase والمفتاح العام Publishable فقط. لا تضف إليه مطلقاً `service_role` أو رمز بوت Telegram.

## 2) تطبيق إعداد قاعدة البيانات

في Supabase افتح **SQL Editor**، ثم افتح الملف:

`supabase/migrations/202610300001_linux_ar_auth_rls.sql`

انسخ محتواه كاملاً وشغّله مرة واحدة.

هذا الملف لا ينشئ الجداول من جديد؛ يعيد استخدام الجداول الخمسة الموجودة لديك. لكنه يستبدل سياسات RLS الحالية لهذه الجداول بسياسات محدودة: المستخدم يقرأ بياناته وتقدمه فقط، بينما إنشاء روابط Telegram وكتابة نتائج الاختبارات يتمان من الخادم فقط. لا تشغّله على مشروع آخر دون مراجعة أسماء الجداول والأعمدة أولاً.

كما يضيف Trigger ينشئ صف `profiles` تلقائياً عند تسجيل مستخدم جديد، ودالة للتحقق من توفر اسم العرض.

## 3) نشر وظيفة الخادم

تحتاج إلى Supabase CLI على جهازك. من داخل المجلد الذي يحتوي مجلد `supabase`:

```bash
supabase login
supabase link --project-ref taeksuuaodwpkmnwbrch
supabase functions deploy telegram-gateway --no-verify-jwt
```

سبب استخدام `--no-verify-jwt` أن الوظيفة تستقبل تحديثات Telegram webhook أيضاً. الوظيفة تتحقق بنفسها من JWT في طلبات الموقع، وتتحقق من سر webhook في تحديثات Telegram.

## 4) إعداد أسرار Telegram

أنت سبق أن أضفت `TELEGRAM_BOT_TOKEN` إلى Supabase Edge Function Secrets، لذلك لا تضعه في ملفات الموقع أو داخل هذه الحزمة.

ولّد قيمة سرية جديدة على جهازك:

```bash
openssl rand -hex 32
```

انسخ القيمة الناتجة، ثم في Supabase افتح **Edge Functions → Secrets** وأضف:

- `TELEGRAM_WEBHOOK_SECRET` = القيمة العشوائية التي ولّدتها.
- `TELEGRAM_CHANNEL` = `@something_37`

لا تغيّر `TELEGRAM_BOT_TOKEN` الحالي ولا تشاركه مع أحد.

## 5) إعداد Telegram webhook

بعد نشر الوظيفة وإضافة الأسرار، شغّل الأوامر التالية في طرفية Bash. سيطلب منك إدخال رمز البوت والسر دون إظهارهما أثناء الكتابة. استخدم نفس قيمة `TELEGRAM_WEBHOOK_SECRET` التي خزنتها في Supabase:

```bash
read -rsp "Telegram bot token: " TELEGRAM_BOT_TOKEN; echo
read -rsp "Webhook secret: " TELEGRAM_WEBHOOK_SECRET; echo
curl -sS -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \\
  --data-urlencode "url=https://taeksuuaodwpkmnwbrch.supabase.co/functions/v1/telegram-gateway" \\
  --data-urlencode "secret_token=${TELEGRAM_WEBHOOK_SECRET}"
unset TELEGRAM_BOT_TOKEN TELEGRAM_WEBHOOK_SECRET
```

تأكد أن رد Telegram يحتوي `"ok":true`. لا ترسل رمز البوت أو السر في المحادثات.

## 6) إعداد عناوين المصادقة

الإعداد الذي ذكرته سابقاً مناسب للتجربة المحلية:

- Site URL: `http://127.0.0.1:8000`
- Redirect URL: `http://127.0.0.1:8000/**`

تأكد من بقاء البريد الإلكتروني مفعّلاً وميزة تأكيد البريد كما هي. عند إنشاء حساب جديد افتح رسالة التأكيد أولاً ثم سجّل الدخول.

## 7) اختبار الإعداد

1. افتح `http://127.0.0.1:8000/linux-arabic-academy/`.
2. أنشئ حساباً ببريدك الإلكتروني واسم عرض، ثم أكّد البريد وسجّل الدخول.
3. افتح موسوعة الأوامر؛ جرّب فتح `pwd` و`mkdir` و`chmod` ولاحظ الشرح المتعمق.
4. نفّذ `pwd`, `ls`, `mkdir practice`, `touch note.txt` في مساحة التدريب.
5. جرّب محرر Python بالمثال `print("Hello Linux!")` ومحرر Bash بأوامر `pwd` و`ls`.
6. اجتز اختبار المبتدئ بنسبة 80% أو أكثر.
7. أنشئ رابط Telegram، افتح البوت `@LinuxArabicAcademyBot` واضغط Start، ثم اشترك في `https://t.me/something_37` وعد إلى الموقع واضغط التحقق.
8. بعد نجاح التحقق يفتح المستوى المتوسط. المستوى المتقدم يتطلب اجتياز اختبار المتوسط أيضاً.

## حدود هذه النسخة بوضوح

- الطرفية محاكاة آمنة داخل المتصفح مع مجموعة أوامر وملفات افتراضية، وليست جلسة Linux حقيقية على خادمك.
- محرر Python/Bash يدعم تشغيل أمثلة تعليمية محدودة فقط؛ لا يشغّل كل تعليمات اللغتين. تشغيل Python/Bash فعلياً يحتاج بيئة حاويات معزولة مستقلة، ولم تُضمَّن هنا حتى لا يتم تنفيذ شيفرة الطلاب على خادم الموقع مباشرة.
- شروحات الأوامر الأكثر شيوعاً مكتوبة بتفصيل خاص، أما بقية الـ1500 فتستخدم شرحاً تعليمياً منظماً مرتبطاً بوصف الأمر. يلزم مراجعة بشرية موسعة لإثراء كل أمر نادر بتفاصيل أدق.
- نصوص الدروس وملف الأوامر موجودة ضمن ملفات الواجهة؛ لذلك الحجب هنا يتحكم في التنقل والاختبارات والتقدم، وليس حماية محتوى ثابتاً من شخص يفحص ملفات الموقع. نتائج الاختبارات وشرط Telegram للتحقق من المستويات محميان من جهة Edge Function.
- لا توجد مهمة حذف تلقائي للحسابات بعد 30 يوماً في هذه الحزمة. لا تفعل حذفاً تلقائياً دون سياسة خصوصية واضحة وآلية استعادة/إشعار.

## إذا لم يعمل الربط

- `is_username_available` غير موجود: لم يتم تشغيل ملف SQL.
- لا تُحمّل بيانات الحساب: راجع سياسات RLS والأعمدة في الجداول الخمسة.
- إنشاء رابط Telegram يفشل: راجع نشر `telegram-gateway` ووجود `TELEGRAM_BOT_TOKEN` و`SUPABASE_SERVICE_ROLE_KEY` ضمن أسرار البيئة الافتراضية.
- البوت لا يربط الحساب: راجع أن webhook رُبط بنفس `TELEGRAM_WEBHOOK_SECRET` وأن البوت يستطيع استقبال رسائل المستخدم.
- التحقق من القناة يفشل: تأكد أن البوت `@LinuxArabicAcademyBot` ما زال مشرفاً في `@something_37` وأن اسم القناة صحيح.

هذه الحزمة جاهزة للاستبدال والنشر، لكن تشغيل SQL ونشر Edge Function وربط webhook خطوات تتم داخل حساباتك ولا يمكن اعتبارها منفذة قبل إتمامها هناك.
